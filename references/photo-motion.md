# 写真×モーションのナレーションCM（品質を毎回そろえる型）

2026-10-12 Lucky v4 で Eugene「過去一いい」「同じ物を作るんやなく、このクオリティを毎回出して」。
正の実物＝`~/scratcher-basket/vsl/remotion/src/LuckyMG4.tsx`（45秒・縦）／部品＝`src/kit/pm.tsx`。
**同じ絵を写すんやない。下の「工程」と「門」を毎回通して、同じ質にそろえる。**

## 何が「過去一」にしたか（3つの掛け算）
1. **分かりやすさ＝本物っぽい写真**：悩みも商品も、見る人が一目で「これは〇〇」と分かる絵。線画・円・矢印・物差し・抽象図は使わん（10/12「線画が分かりづらい」「アリを見たらアリ」・相手は40代以上）
2. **動き＝写真の上でモーション**：写真をゆっくり上下に動かすだけは「寂しい」（v3で却下）。1場面に動きを2〜3個重ねる（下の語彙）
3. **意味と動きを一致させる**：動きは飾りやなく、台詞の意味をそのまま絵にする（「肉がのる」→字が落ちてウエストに乗る／「締めない」→細いゴムの写真が割れてゴムが消える／「がっかり」→写真が傾いて落ちる）

## 工程（この順・飛ばさん）
1. **悩みを客の声で決める**：VOC（他社のレビュー等）から、場面ごとの具体的な悩みを取る。客の言い回しをそのまま台詞に。分からん言い方（例「丸まる」）は入れん
2. **台本→声**：narration スキル（ElevenLabs v4）。標準語。whisper の文字時刻＝網目
3. **場面の設計表を先に書く**（ファイルに残す）：列＝秒／台詞／写真（何が写るか）／見せる所（写真の中の 0〜1 座標）／動き2〜3個（語彙から）／効果音（動きごと）／文字（どこに・どの mode）
4. **写真を Codex で作る**（聞かずに作ってええ）：
   - 悩み＝白黒寄り・顔なし・**本人の手で場所を示す**（つまむ・押さえる）・広告なので大げさに・背景は無地の濃い色・**端から端まで全面**（「余白・枠・貼り合わせの縁は作らない」と書く。上下に空きを指定すると貼り合わせ絵になる＝10/12実測）
   - 解決後＝同じ向き・同じ光でカラー。商品が写る物は実物と照合（DESIGN_CHECK）
   - 妊婦に見える・手の位置が違う等は作り直し（1枚あたり最大3回）
5. **人の切り抜き**：`scripts/cutout.py in.png out.png`（無料・手元）。巨大文字の前に人を立たせる・人が滑り込む、に使う
6. **組む**：`import * from "./kit/pm"`（`setTheme` でブランドの色と書体）→場面だけ書く。音は `mix_mg4.py` 型（声＋場面ごとの和音＋効果音を1本に混ぜる）
7. **門（機械）**：`scripts/qa_pm.sh <CM.tsx> <完成.mp4> <混ぜた音.wav>` が全部 OK
8. **門（目）**：作った会話を見てへん別の係（サブエージェント）に、🆕10/18〜 mp4 と `scripts/shinsa_zairyo.py` の材料を渡して動画で審査（motion-cm/references/douga_shinsa.md）。最後は `scripts/nouhin_gate.py`。基準＝①寂しい所／動きすぎで分からん所 ②40代が一目で分かるか ③高級感・崩れ。直す所を最大6つ→その場面だけ直す→もう1周（最大3周）
9. **見せる**：Finder で開く（`open -R`）。前の版は残す

## 動きの語彙（kit/pm.tsx の部品）
| 意味 | 動き | 部品 |
|---|---|---|
| 話の入り・数字（40代・30日） | 巨大な文字の前に人の影が滑り込み→写真に変わる／数を上げながら数える | 巨大 div ＋ `Layer`（cut_*.png・brightness 0→1）／`Math.round(n*p)` |
| ここを見て | その場所へ寄る＋周りを沈める＋光の玉が脈打つ | `Layer`(原点＝見せる所) ＋ `Vig` ＋ `Glow` |
| 細部の証拠（つまんだ肉・帯） | 拡大の小窓がその場所から飛び出す | `Inset` |
| 場面の入り | 横から滑り込む（ぶれ）／下からせり上がる／短冊で開く | `SceneX enter="whip"/"up"` ・ `Strips` |
| 強い一言（凹まない・目立つ） | 大きく押される＋画面が揺れる／巨大な1字が人の後ろで金に変わる | `KW mode="stamp"` ＋ `shake` |
| 形・線（段・帯） | その線に沿って光が走る（線は描かん） | `Glint rot=…` |
| 乗る・落ちる | 字が上から落ちてその物の上に着地 | `KW mode="drop"`（y＝着地点の座標） |
| がっかり・沈む | 写真が傾いて落ちる・字がうなだれる | `KW droopAt` ＋ 写真の rotate/translate |
| 前→後（白黒→カラー） | 光の帯が横切って入れ替わる | clipPath ＋ 光の帯 |
| 無くす（細いゴム等） | 写真がその線で上下に割れて線が消える | clipPath 2枚＋translate |
| 締まる・整う | 字間が広い所から締まる | `KW mode="snap"` |
| 色・サイズ | 札が左から1枚ずつ落ちる→光が1回／印が1つずつ点く | 落下＋`Glint`／丸い印の点灯 |

## 🔒 VSLの説明の場面に差し込む型（2026-10-12 K1「壁」v3・Eugene「めっちゃ綺麗です」）
正の実物＝`~/scratcher-basket/vsl/K1_kabe/remotion/src/pm_k1.tsx`（22場面）・絵＝`K1_kabe/pm/`・設計表＝`pm/設計表.md`・審査3周＝6.5→7→8点。
CMを新しく作るんやなく、**既存のVSLの「図」の場面だけ**を写真×モーションに置き換える時の手順。

**こうやると、こうなる**
1. **絵は本編と同じ見た目で作る**（3DのVSLなら3D・実写なら実写）→ 図の場面に移っても絵の調子が変わらん（v2の線画は「平らで浮く」が弱点やった）
2. **「図」を描かず、その言葉が起きとる物を1枚で写す**（「においの目印」＝柱の爪あとが光る／「4部屋」＝4部屋のミニチュア／「ゼロに戻る」＝ゴミ袋に落ちる爪とぎ）→ 40代が一目で分かる
3. **光（Glow）は「見せたい物そのもの」に置く**（爪あと・肉球のあいだ・空いた床）→ 線や矢印なしで「ここ」が伝わる
4. **場面＝データ1行（img・cam・glow・glint・kw）にして、効果音を同じ数字から自動で出す**（`cues()`）→ 音と動きがずれん・直しが1行で済む
5. **既存VSLへは import を1行替えるだけ**（`Mg/isMg/MG_SFX` と同じ形で書き出す）→ 他の場面に触らん・前の版に戻せる

**手順（K1でやった順）**
1. `/eizo-iitoko` の wari.json で、図の場面を `setsumei → motion-cm/photo-motion` に割り振る
2. 場面ごとに「何が写る1枚か」を書く→ `gen_keyframes.py` 形式の beats.json → Codex で生成（2本並列・20枚で約35分）
3. 2:3 の絵は真ん中で 9:16 に切ってから使う（`pm/crop.py`。そのまま使うと横に潰れる）
4. 商品が写る絵は実物写真と並べて照合（K1は縁が太いねじりロープに化けた1枚を作り直し）
5. 絵ごとに、見せたい所の座標を 1080×1920 で決めて glow・寄りの中心に入れる→止め絵を数枚書き出して位置を確かめる
6. 書き出し→ -16 LUFS → 黒0 → 0.5秒ごとのコマ一覧を別の係に渡して審査（最大3周）

**審査で毎回直った所＝最初から守る数字**
- キーワードは**上の空き（y≈290〜440）**。字幕の箱（下10〜25%）と物の上には置かん。主役の字は **96〜116px・金**、添えの字は 70〜84px
- 文字の後ろが明るい時は、左を暗くする帯（shade）か上の暗いグラデを敷く
- **場面の最初の1秒以内に何か動く**（光の帯・キーワード・光）。最後の0.5秒で初めて言葉が出る場面は「寂しい」と言われる
- 上から落ちる文字（drop）は画面の上で切れる→上の方では pop を使う
- 短冊で開く（Strips）は1コマ目が黒くなる→使わん
- 拡大の小窓（Inset）は寄った中身が何か分からん＝使わん（K1で外した）
- 審査のコマ一覧は、場面の終わり0.25秒を外す（次の場面が滑り込む途中を「文字が切れた」と誤判定する）

**スキルと違えた所（今回の判断・次も同じでええ）**
- 絵は「本物っぽい写真」やなく **本編と同じ3D** にした（VSLの中で調子をそろえるため）。本物っぽさ＝「何が写っとるか一目で分かる」の方で守った
- cutout.py（人の切り抜き）は使わんかった（人が出ん場面ばかり）
- 🟡 音は1本に混ぜず、VSL本体と同じく Remotion の中で鳴らした（最大0.016秒ずれる）。qa_pm.sh も使わず、音量と黒は ffmpeg で個別に測った（VSL本体が `<Audio>` を何本も持つので qa_pm.sh の「1本」検査が合わん）
